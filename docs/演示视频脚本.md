# 演示视频脚本（5-8 分钟）

> 目标：6 分 40 秒左右，1920×1080，MP4（H.264），普通话讲解，可配字幕。
> 录制前请先配置好真实 DeepSeek Key，并跑通 `scripts/smoke-test.ps1`。

## 一、录制前准备

- [ ] 浏览器缩放 100%，隐藏书签栏，关闭无关标签页
- [ ] 使用 1920×1080 分辨率，OBS 录制 30fps
- [ ] 麦克风测试，环境安静
- [ ] 登录管理员账号 `13800138000 / 123456`（后台演示用）
- [ ] 准备普通用户账号 `13800138001 / 123456`（前台演示用）
- [ ] 确认 `/api/ai/health` 返回 `configured: true`
- [ ] 准备一个备用录屏：本地兜底模式（`AI_MOCK_ENABLED=true`）
- [ ] 视频中不要露出 `.env`、API Key、个人手机号/身份证

## 二、分镜与讲解词

### 0:00-0:25 开场

**画面**：首页顶部，LOGO 和轮播图。

**讲解词**：

> 大家好，我们是 Web 重生办事处。我们的作品是「拾光旅行」，一个面向大学生的校园旅游电商平台。它不仅有完整的线路、酒店、景点、游记和拼团业务，还接入了 DeepSeek 大模型，提供 AI 行程规划、AI 旅行管家和 AI 内容初审。

### 0:25-1:10 项目介绍与首页

**画面**：缓慢滚动首页，展示分类导航、AI 入口、学生特惠、热门目的地、游记。

**讲解词**：

> 大学生出行有三个特点：预算有限、时间碎片化、信息分散。传统 OTA 功能复杂，攻略和预订割裂；社交平台有内容，但不能直接下单。拾光旅行把「搜索、预订、内容、社交、校园权益」放在一个平台里。
>
> 首页可以看到学生特惠、周末游、海岛度假等分类，也有 AI 行程入口和全站悬浮的 AI 旅行管家。

### 1:10-2:20 AI 行程规划

**画面**：点击「AI 行程」，选择三亚，3 天，人均 2500 元，选择海岛和美食，点击生成。等待结果。

**讲解词**：

> 我们先演示 AI 行程规划。输入目的地三亚、三天、人均两千五，选择海岛和美食偏好。
>
> 点击生成后，后端会先做 IP 限流和缓存检查，然后从平台数据库召回真实线路、酒店和景点。注意，AI 不是凭空生成，它拿到的是一份受控上下文，里面每个产品都有平台 ID。
>
> 生成结果包含逐日时间线、交通、住宿、景点和餐饮安排，还有预算估算和出行提示。下面的酒店卡片来自平台真实数据，点击可以直接进入预订页。
>
> 如果模型返回了不存在的产品 ID，后端会直接丢弃；价格和名称也由后端回填，不由模型编造。

**画面**：滚动行程结果，展示预算条、酒店推荐卡片；点击酒店卡片进入详情。

### 2:20-3:10 AI 旅行管家

**画面**：返回首页，点击右下角「AI 旅行管家」，输入「三亚三天怎么玩？」。

**讲解词**：

> 第二个能力是 AI 旅行管家。它挂载在全站，用户在任何一个页面都可以打开。
>
> 我们问它：三亚三天怎么玩？它会结合平台线路、酒店和景点回答，并在下方给出可点击的引用卡片。回答中的产品同样来自平台数据，不是模型编造的。
>
> 如果模型不可用，系统会返回明确标注「本地兜底」的检索结果，保证演示不中断。

**画面**：展示回答和引用卡片，点击一个景点或线路卡片。

### 3:10-4:00 核心业务：线路与酒店预订

**画面**：进入线路详情，选择日期和人数，提交订单；进入酒店详情，选择房型，填写入住人，提交订单。

**讲解词**：

> AI 之外，平台的核心业务是完整的电商闭环。
>
> 线路支持目的地、价格、天数筛选，详情页展示行程、费用包含和不包含、库存和评价；下单后生成订单，可以在个人中心查看。
>
> 酒店预订支持房型选择和动态入住人表单。社团出行时，可以一次填写多位同学的姓名、手机号和身份证信息，后端以 JSON 存储，解决团体出行统计难的问题。

### 4:00-4:55 后台与 AI 内容初审

**画面**：登录管理员，进入后台内容审核，打开一条待审核游记，点击「AI 复核」。

**讲解词**：

> 这是管理后台。平台对游记、结伴和评论有完整的内容审核流程。
>
> 管理员打开一条待审核内容，除了敏感词检测，还可以点击「AI 复核」。AI 会返回风险等级、评分、风险分类、原因和处置建议，例如广告引流、隐私泄露、人身攻击等。
>
> 注意，AI 只给建议，最终通过还是拒绝由管理员决定。每次审核都会写入审核记录，支持追溯。

### 4:55-5:40 技术架构与 AI 方案

**画面**：切换到技术文档或架构图页面（可用 PDF 第 9 页、第 12 页）。

**讲解词**：

> 技术架构上，前端是 Vue 3，后端是 Spring Boot 3，数据库 MySQL，缓存 Redis，部署用 Docker Compose 和 Nginx。
>
> AI 部分是一个独立的服务层：先限流，再查缓存，然后做 RAG 召回，构造提示词，调用 DeepSeek 的 OpenAI 兼容接口，最后做 JSON 解析、产品 ID 白名单校验和数据回填。
>
> 我们做了几层优化：Redis 加进程内两级缓存、按 IP 限流、超时重试、JSON 模式降级，以及模型不可用时的本地兜底。这样既控制成本，也保证演示稳定。

### 5:40-6:20 创新点与测试

**画面**：技术文档第 25-26 页（总结与创新点），或 PPT 创新点页。

**讲解词**：

> 项目的创新点可以概括为五点：
>
> 第一，面向旅游电商的 RAG 落地，让模型读取真实产品；第二，结构化输出加 ID 白名单和数据回填，降低幻觉；第三，两级缓存、限流和本地兜底，保证可用性和成本；第四，规则加大模型的混合内容审核；第五，通过 OpenAI 兼容协议解耦模型供应商。
>
> 测试方面，我们验证了后端打包、前端构建、数据库导入、AI 行程、问答、初审、缓存命中、未授权拦截和本地兜底。

### 6:20-6:40 收尾

**画面**：回到首页，展示 AI 入口和平台 LOGO。

**讲解词**：

> 拾光旅行希望让大学生「少切换几个 App，多留一点时间给旅途」。感谢各位评审观看，欢迎批评指正。

## 四、录制与剪辑

1. 使用 OBS 录制，输出 MP4，视频编码 H.264，分辨率 1920×1080，帧率 30fps。
2. 讲解词可分段录制，后期对齐画面；语速控制在每分钟 220-260 字。
3. 字幕使用 `docs/演示视频字幕.srt`，导入剪映/Premiere 后微调时间轴。
4. 背景音乐音量控制在 -28dB 左右，不要盖过人声。
5. 导出前检查：时长 5-8 分钟、声音清晰、无密钥/个人信息、AI 结果正常。
6. 建议同时导出一份 720p 备份，防止评审平台上传失败。

## 五、异常预案

- **AI 超时/限流**：提前录制备用片段，使用 `AI_MOCK_ENABLED=true` 的本地兜底结果，并在讲解中说明“这是本地兜底，正式环境走真实模型”。
- **网络中断**：使用本地已生成的行程截图/录屏，不现场等待。
- **后台登录失败**：提前确认 `DEMO_DATA_ENABLED=true`，或用 `scripts/smoke-test.ps1` 检查账号。
- **页面布局异常**：浏览器缩放恢复 100%，清空缓存后重试。
